# 10장. 고차 함수: 람다를 파라미터와 반환값으로 사용

## 한눈에 보기

이 장은 "함수를 인자로 받거나 반환하는 함수는 어떻게 만들고, 람다의 비용은 어떻게 없애며, 람다 안의 `return`은 어디로 돌아가는가?"에 답한다.

- 고차 함수(higher-order function)는 다른 함수를 파라미터로 받거나 반환값으로 돌려주는 함수다. 함수 타입(`(Int) -> String`)으로 그 모양을 선언한다.
- 함수 타입 파라미터에는 기본값을 줄 수 있고, `?`를 붙여 null도 허용할 수 있다.
- 람다는 기본적으로 객체로 만들어져 비용이 있지만, `inline` 함수로 선언하면 호출 지점에 코드가 복사되어 그 비용이 사라진다.
- `inline` 함수에 넘긴 람다 안의 `return`은 람다가 아니라 **바깥 함수**를 끝낸다. 람다만 끝내려면 레이블이나 익명 함수를 쓴다.

## 핵심 개념

### 함수 타입

`(파라미터 타입들) -> 반환 타입` 형태로 쓴다. 반환값이 없으면 `Unit`이다. 람다에서 파라미터 타입을 추론할 수 있으면 생략한다.

```kotlin
fun main() {
    val add: (Int, Int) -> Int = { a, b -> a + b }
    val greet: (String) -> Unit = { println("hi $it") }
    println(add(2, 3))
    greet("kotlin")
    // 출력:
    // 5
    // hi kotlin
}
```

**Java 비교:** Java에서는 `BiFunction<Integer, Integer, Integer>`, `Consumer<String>`처럼 용도별 함수형 인터페이스를 골라야 한다. Kotlin은 함수 타입 문법 하나로 해결한다.

> 💡 **눈높이 설명**
>
> Java의 `Function`, `Supplier`, `Predicate` 등은 모양이 같아도 이름이 달라서 메서드 이름(`apply`, `get`, `test`)까지 외워야 한다. Kotlin의 함수 타입은 그냥 변수를 `f(x)`로 부르면 된다. 이름 없는 구조 타입이라 "함수가 들어갈 자리"만 표시한다고 생각하면 된다.

### 인자로 전달받은 함수 호출

함수 타입 파라미터는 일반 함수처럼 `이름(인자)`로 호출한다. 마지막 파라미터가 함수 타입이면 호출할 때 괄호 밖으로 람다를 뺄 수 있다.

```kotlin
fun twice(x: Int, op: (Int) -> Int): Int = op(op(x))

fun main() {
    println(twice(3) { it * 2 })
    // 출력: 12
}
```

### 기본값과 널이 될 수 있는 함수 타입

함수 타입 파라미터에도 기본값을 줄 수 있다. null을 허용하려면 함수 타입 전체를 괄호로 감싸고 `?`를 붙인다. null 가능 함수는 `?.invoke(...)`로 호출한다.

```kotlin
fun log(msg: String, format: (String) -> String = { it }) = println(format(msg))

fun maybe(x: Int, callback: ((Int) -> Unit)? = null) {
    callback?.invoke(x)
}

fun main() {
    log("a")
    log("b") { "[$it]" }
    maybe(1)
    maybe(2) { println("got $it") }
    // 출력:
    // a
    // [b]
    // got 2
}
```

`(Int) -> Unit?`는 "`Unit?`을 반환하는 함수"라서 의미가 다르다. 함수 자체를 nullable로 만들려면 `((Int) -> Unit)?`로 쓴다.

### 함수를 함수에서 반환

조건에 따라 다른 동작을 골라 돌려줄 때 쓴다.

```kotlin
fun discount(vip: Boolean): (Int) -> Int =
    if (vip) { price -> price * 8 / 10 } else { price -> price }

fun main() {
    val f = discount(true)
    println(f(1000))
    println(discount(false)(1000))
    // 출력:
    // 800
    // 1000
}
```

### 람다로 중복 줄이기

달라지는 부분만 함수 타입 파라미터로 빼면 비슷한 함수 여러 개를 하나로 합칠 수 있다.

```kotlin
data class Order(val price: Int, val vip: Boolean)

fun total(orders: List<Order>, cond: (Order) -> Boolean): Int =
    orders.filter(cond).sumOf { it.price }

fun main() {
    val orders = listOf(Order(100, true), Order(200, false), Order(300, true))
    println(total(orders) { it.vip })
    println(total(orders) { it.price > 150 })
    // 출력:
    // 400
    // 500
}
```

### 인라이닝이 작동하는 방식

람다를 쓰면 보통 함수 객체가 만들어지고, 캡처하는 변수가 있으면 호출마다 객체를 새로 할당한다. `inline`을 붙이면 컴파일러가 **함수 본문과 람다 본문을 호출 지점에 그대로 복사**해 넣어서 객체 생성과 호출 비용이 사라진다.

```kotlin
inline fun measure(block: () -> Unit) {
    val start = System.nanoTime()
    block()
    println("걸린 시간 측정됨: ${System.nanoTime() - start >= 0}")
}

fun main() {
    measure { println("작업 중") }
    // 출력:
    // 작업 중
    // 걸린 시간 측정됨: true
}
```

> 💡 **눈높이 설명**
>
> C의 매크로나 IDE의 "Inline Method" 리팩터링과 비슷하다. 호출하는 자리에 메서드 본문이 펼쳐진다고 생각하면 된다. Java의 JIT가 하는 인라이닝은 런타임 최적화라 개발자가 제어할 수 없지만, Kotlin의 `inline`은 컴파일 시점에 일어나고 **람다 인자까지** 함께 인라인된다는 점이 다르다.

### 인라인 함수의 제약

- 인라인된 람다는 호출 지점에 펼쳐지므로, 람다를 **다른 변수에 저장하거나 인라인되지 않는 곳에 넘기는** 일은 막힌다.
- 일부 람다만 인라인하고 싶지 않으면 그 파라미터에 `noinline`을 붙인다.
- 인라인 함수는 본문이 호출 지점에 복사되므로 `public` 인라인 함수가 `private` 멤버를 직접 쓰는 것도 제한된다.

```kotlin
inline fun run2(inlined: () -> Unit, noinline stored: () -> Unit) {
    inlined()
    val saved = stored       // noinline이라 변수에 저장 가능
    saved()
}

fun main() {
    run2({ println("a") }, { println("b") })
    // 출력:
    // a
    // b
}
```

### 컬렉션 연산 인라이닝

`filter`, `map` 같은 컬렉션 함수는 `inline`으로 선언되어 있어서 람다가 객체로 만들어지지 않는다. 일반 컬렉션 함수는 단계마다 중간 리스트를 만든다(6장). 원소가 많은 체인에서는 시퀀스(`asSequence`)가 중간 컬렉션을 없애 주지만, 시퀀스의 연산은 `inline`이 아니라서 람다가 객체로 만들어진다. 어느 쪽이 유리한지는 데이터 크기를 보고 판단한다.

### 언제 함수를 인라인으로 선언할지

- **람다를 파라미터로 받는 함수**일 때 효과가 크다. 일반 함수(람다 없음)는 JVM이 이미 인라인하므로 `inline`의 이득이 거의 없다.
- 본문이 큰 함수를 `inline`으로 만들면 호출 지점마다 바이트코드가 복사되어 크기만 커진다. 작은 함수에 쓴다.
- 일반 라이브러리 함수를 만들 때는 호환성 문제도 있으니 신중하게 쓴다.

### 자원 관리: `withLock`, `use`, `useLines`

`inline`과 람다의 조합은 Java의 `try-with-resources`나 `synchronized`를 대체한다. `withLock { }`은 락을 잡고 풀고, `use { }`는 `Closeable` 자원을 블록이 끝나면 닫고, `useLines { }`는 파일의 줄 시퀀스를 처리하고 닫는다.

```kotlin
import java.io.File

fun main() {
    val f = File.createTempFile("demo", ".txt").apply { writeText("a\nb\nc") }
    val count = f.bufferedReader().use { reader -> reader.readLines().size }
    println(count)
    val first = f.useLines { lines -> lines.first() }
    println(first)
    // 출력:
    // 3
    // a
}
```

**Java 비교:**

```java
// Java
try (BufferedReader r = new BufferedReader(new FileReader(f))) {
    return r.readLine();
}
```

Kotlin에는 `try-with-resources` 문법이 없다. `use`는 언어 기능이 아니라 `inline` 확장 함수다.

### 람다 안의 `return`: 둘러싼 함수에서 반환

`inline` 함수에 넘긴 람다 안에서 `return`을 쓰면 **람다를 둘러싼 바깥 함수**가 반환된다. 이를 비로컬 반환(non-local return)이라고 한다. `forEach`가 대표적이다.

```kotlin
fun findFirstEven(nums: List<Int>): Int? {
    nums.forEach {
        if (it % 2 == 0) return it    // findFirstEven 자체가 끝남
    }
    return null
}

fun main() {
    println(findFirstEven(listOf(1, 3, 4, 6)))
    // 출력: 4
}
```

> 💡 **눈높이 설명**
>
> Java의 `list.forEach(x -> { return; })`에서 `return`은 람다만 끝내고 루프는 계속 돈다. Kotlin의 `forEach`는 `inline`이라 람다가 `for` 루프 본문처럼 펼쳐지므로 `return`이 바깥 함수까지 끝낸다. 인라인되지 않는 람다에서는 이런 비로컬 반환이 허용되지 않는다.

### 레이블을 사용한 return

람다만 끝내고 싶다면 `return@레이블`을 쓴다. 레이블 이름은 보통 람다를 받는 함수 이름이다(`return@forEach`). 직접 `레이블@ { }`로 붙일 수도 있다.

```kotlin
fun main() {
    listOf(1, 2, 3, 4).forEach {
        if (it == 2) return@forEach      // continue처럼 동작
        print("$it ")
    }
    println()
    // 출력: 1 3 4
}
```

### 익명 함수: 기본적으로 로컬 return

`fun(x: Int): Boolean { ... }` 형태의 익명 함수(anonymous function)에서 `return`은 **그 익명 함수만** 끝낸다. 레이블 없이도 로컬 반환이 된다.

```kotlin
fun main() {
    val evens = listOf(1, 2, 3, 4).filter(fun(n): Boolean {
        if (n % 2 != 0) return false
        return true
    })
    println(evens)
    // 출력: [2, 4]
}
```

람다에는 반환 타입을 쓸 수 없지만 익명 함수는 쓸 수 있고, `return`의 의미가 명확해진다.

## Java와 비교

| 항목 | Java | Kotlin |
|---|---|---|
| 함수 타입 | `Function`, `Supplier` 등 인터페이스 선택 | `(A, B) -> R` 문법 |
| 함수 호출 | `f.apply(x)` 등 메서드 이름 | `f(x)` |
| null 가능 함수 | 객체가 null일 수 있음 | `((A) -> R)?`, `?.invoke` |
| 람다 비용 | 호출 방식에 따라 `invokedynamic` | 기본은 객체, `inline`으로 제거 |
| 자원 관리 | `try-with-resources` | `use { }` (인라인 확장 함수) |
| 람다 안 `return` | 람다만 종료 | `inline` 람다: 바깥 함수 종료 |
| 람다만 종료 | `return` | `return@레이블` 또는 익명 함수 |

## 헷갈리기 쉬운 점

- `(Int) -> Unit?`와 `((Int) -> Unit)?`는 다르다. 앞은 반환 타입이 nullable, 뒤는 함수 자체가 nullable이다.
- 비로컬 반환은 `inline` 함수의 람다에서만 된다. 일반 고차 함수에서 람다 안에 `return`을 쓰면 컴파일 오류다.
- `forEach` 안의 `return`은 `continue`가 아니라 **함수 탈출**이다. `continue`처럼 쓰려면 `return@forEach`다.
- `inline`은 성능을 높이는 만능 스위치가 아니다. 큰 함수에 붙이면 코드 크기만 늘어난다.
- `inline` 함수의 람다 파라미터를 변수에 저장하거나 다른 곳에 넘기려면 `noinline`이 필요하다.
- `use`는 언어 키워드가 아니다. `Closeable`의 확장 함수라서 `Closeable`이 아닌 객체에는 쓸 수 없다.

1. 함수 타입 `(String, Int) -> Boolean`을 받는 함수 `check`를 선언하고 호출하는 코드를 써 보라.

<details>

```kotlin
fun check(f: (String, Int) -> Boolean) = f("abc", 2)
fun main() = println(check { s, n -> s.length > n })
// 출력: true
```

</details>

2. `callback: (() -> Unit)? = null`을 안전하게 호출하는 방법은?

<details>
<summary>답 보기</summary>

`callback?.invoke()`로 호출한다. null이면 아무 일도 일어나지 않는다.

</details>

3. `inline` 함수가 일반 고차 함수보다 효율적인 이유는?

<details>
<summary>답 보기</summary>

호출 지점에 함수 본문과 람다 본문이 복사되어 람다 객체 생성과 호출 비용이 없어진다. 캡처 변수가 있어도 객체를 만들지 않는다.

</details>

4. `forEach { if (...) return }`의 `return`은 어디로 돌아가는가? `continue` 효과를 내려면?

<details>
<summary>답 보기</summary>

`forEach`가 `inline`이라 `return`은 바깥 함수를 종료한다. `continue` 효과는 `return@forEach`로 낸다.

</details>

5. `noinline`은 언제 필요한가?

<details>
<summary>답 보기</summary>

`inline` 함수의 람다 파라미터를 변수에 저장하거나 인라인되지 않는 다른 함수에 전달해야 할 때 필요하다.

</details>
