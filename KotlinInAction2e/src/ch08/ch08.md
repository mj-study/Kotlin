# 8장. 기본 타입, 컬렉션, 배열

## 한눈에 보기

이 장은 "Java의 `int`/`Integer`, `void`, `Object`, 컬렉션, 배열은 Kotlin에서 어떻게 대응되는가?"에 답한다.

- Kotlin에는 원시 타입(primitive type)과 래퍼 타입의 구분이 문법에 없다. `Int` 하나만 쓰고, 컴파일러가 가능하면 `int`로, 필요하면 `Integer`로 바꿔 준다.
- `Any`는 모든 non-null 타입의 뿌리, `Any?`는 null까지 포함한 진짜 뿌리다. `Unit`은 `void`에 대응하지만 실제 값을 가진 타입이고, `Nothing`은 "절대 반환하지 않음"을 나타낸다.
- 컬렉션은 읽기 전용(`List`)과 변경 가능(`MutableList`) 인터페이스로 나뉜다.
- Java에서 온 컬렉션은 플랫폼 타입으로 보이므로 경계에서 널 가능성과 가변성을 직접 판단해야 한다.
- 배열은 컬렉션보다 쓸 일이 적고, 원시 타입 배열(`IntArray` 등)이 따로 있다.

## 핵심 개념

### 원시 타입과 기본 타입

Kotlin에서는 `Int`, `Double`, `Boolean` 등을 그냥 쓴다. 컴파일된 바이트코드에서 일반 변수·프로퍼티·함수 인자는 `int`, `double` 같은 JVM 원시 타입이 되고, 제네릭 인자(`List<Int>`)처럼 객체가 필요한 곳에서만 `Integer`로 박싱된다.

```kotlin
fun main() {
    val a: Int = 10               // 바이트코드에서는 보통 int
    val list: List<Int> = listOf(1, 2, 3)   // 제네릭 안에서는 Integer
    println(a + list.sum())
    // 출력: 16
}
```

> 💡 **눈높이 설명**
>
> Java에서는 `int`와 `Integer`를 개발자가 직접 골라야 하고, 둘의 차이(null 가능, `==` 비교 함정, 오토박싱 비용)가 버그 원인이 된다. Kotlin은 "타입은 `Int` 하나, 어떤 모양으로 저장할지는 컴파일러가 결정"하게 해서 이 선택 부담을 없앴다.

숫자 타입 간 변환은 자동으로 되지 않는다. `Int`를 `Long` 변수에 넣으려면 `toLong()`처럼 명시적으로 변환한다.

```kotlin
fun main() {
    val i = 3
    // val l: Long = i       // 컴파일 오류
    val l: Long = i.toLong()
    println(l)
    // 출력: 3
}
```

### 널이 될 수 있는 기본 타입

`Int?`처럼 `?`가 붙으면 null을 담아야 하므로 `Integer`로 저장된다. 7장의 `?.`, `?:`를 그대로 쓴다.

```kotlin
fun main() {
    val a: Int? = null
    val b: Int? = 5
    println(a ?: 0)
    println(b?.plus(1))
    // 출력:
    // 0
    // 6
}
```

**Java 비교:** Kotlin `Int?`는 Java `Integer`에 대응한다. 그리고 `List<Int>`의 요소 타입도 `Integer`다.

> 💡 **눈높이 설명**
>
> `Int?`끼리 `==`로 비교하면 Java의 `Integer == Integer`(참조 비교 함정)와 달리 값(`equals`)을 비교한다. Kotlin의 `==`는 항상 `equals`로 번역되고, 참조 비교는 `===`다.

### Any와 Any?: 코틀린 타입 계층의 뿌리

`Any`는 Java의 `Object`와 비슷한 최상위 타입이지만, **null이 아닌 값만** 담는다. null까지 담는 진짜 최상위는 `Any?`다. 원시 타입(`Int` 등)도 `Any`의 하위 타입이다.

```kotlin
fun main() {
    val x: Any = 42
    val y: Any? = null
    println(x)
    println(y)
    // 출력:
    // 42
    // null
}
```

`Any`에는 `equals`, `hashCode`, `toString` 세 메서드만 있다. `wait`/`notify` 같은 나머지 `Object` 메서드는 `Any`에 없다.

### Unit 타입: 코틀린의 void

반환값이 없는 함수의 반환 타입이다. 생략하면 `Unit`으로 간주된다. `void`와 달리 **타입이자 값**이어서 제네릭 인자로 쓸 수 있다.

```kotlin
fun log(msg: String): Unit { println(msg) }

fun main() {
    log("hi")
    val r: Unit = log("again")
    println(r)
    // 출력:
    // hi
    // again
    // kotlin.Unit
}
```

> 💡 **눈높이 설명**
>
> Java에서 `Callable<Void>`를 만들면 `return null;`을 억지로 써야 하는 이유는 `void`가 값이 없는 키워드이기 때문이다. Kotlin의 `Unit`은 "값이 하나뿐인 타입"이라 `() -> T` 형태의 제네릭 코드가 반환이 있든 없든 똑같이 동작한다.

### Nothing 타입: 이 함수는 결코 반환되지 않는다

항상 예외를 던지거나 무한 루프라서 정상 종료가 없는 함수의 반환 타입이다. 컴파일러가 "여기서 흐름이 끝난다"는 사실을 알게 되어, 엘비스 연산자 오른쪽에 쓰면 왼쪽을 non-null로 만들어 준다.

```kotlin
fun fail(msg: String): Nothing = throw IllegalStateException(msg)

fun main() {
    val name: String? = "kotlin"
    val n: String = name ?: fail("name is null")   // 이후 n은 non-null
    println(n)
    // 출력: kotlin
}
```

표준 라이브러리의 `TODO()`도 `Nothing`을 반환하는 함수다.

### 읽기 전용과 변경 가능한 컬렉션

Kotlin의 컬렉션 인터페이스는 두 층이다. `List`, `Set`, `Map`은 읽기 전용이고, `MutableList`, `MutableSet`, `MutableMap`은 추가·삭제 메서드를 갖는다. 읽기 전용 인터페이스는 읽기 메서드만 있다.

```kotlin
fun main() {
    val ro: List<Int> = listOf(1, 2, 3)
    // ro.add(4)              // 컴파일 오류
    val mu: MutableList<Int> = mutableListOf(1, 2, 3)
    mu.add(4)
    println(mu)
    // 출력: [1, 2, 3, 4]
}
```

함수가 컬렉션을 **읽기만** 하면 `List`로, **바꾸어야** 하면 `MutableList`로 받는다. 시그니처만 봐도 부작용 여부를 알 수 있다.

> 💡 **눈높이 설명**
>
> Java의 `List`는 읽기·쓰기 메서드가 한 인터페이스에 섞여 있어서, `List.of()`로 만든 불변 리스트에 `add`를 호출하면 컴파일은 되고 런타임에 `UnsupportedOperationException`이 난다. Kotlin은 이를 컴파일 시점으로 당긴다. 단, `List`는 "이 참조로는 못 바꾼다"는 뜻일 뿐 불변 객체라는 보장은 아니다. 같은 객체를 가리키는 `MutableList` 참조가 따로 있으면 그쪽에서 바꿀 수 있다.

### 자바에서 선언한 컬렉션은 코틀린에서 플랫폼 타입으로 보임

Java가 선언한 `java.util.List<String>`은 Kotlin에서 `(Mutable)List<String!>!` 식의 플랫폼 타입으로 보인다. 읽기 전용으로 쓸지, 변경 가능으로 쓸지, 원소가 null일 수 있는지를 컴파일러가 알 수 없으므로 **사용하는 쪽이 정해야** 한다.

```kotlin
fun main() {
    val javaList: java.util.ArrayList<String> = java.util.ArrayList()
    javaList.add("a")
    val view: List<String> = javaList        // 읽기 전용으로 받기
    println(view)
    // 출력: [a]
}
```

선택 기준은 다음과 같다.

- Java 코드가 바꾸지 않고 Kotlin도 읽기만 한다면 `List<T>`.
- Java 코드가 내용을 바꿀 가능성이 있다면 `MutableList<T>`.
- 원소가 null일 수 있다면 `List<T?>`, 리스트 자체가 null일 수 있다면 `List<T>?`.

### 성능과 상호운용을 위해 객체의 배열이나 원시 타입의 배열을 만들기

배열은 `Array<T>`다. 일반 클래스이고 `arrayOf`, `Array(n) { }` 등으로 만든다. 원시 타입을 담을 때는 박싱을 피하기 위해 `IntArray`, `DoubleArray` 같은 전용 클래스를 쓴다. 이들은 JVM의 `int[]`, `double[]`에 대응한다.

```kotlin
fun main() {
    val objs: Array<String> = arrayOf("a", "b")
    val squares = IntArray(4) { it * it }        // int[]
    println(objs.joinToString())
    println(squares.joinToString())
    // 출력:
    // a, b
    // 0, 1, 4, 9
}
```

`Array<Int>`는 `Integer[]`이므로 느리고 메모리를 더 쓴다. 숫자 배열은 `IntArray`를 쓴다. 컬렉션처럼 `forEach`, `map`, `filter` 같은 확장 함수도 배열에 쓸 수 있다.

```kotlin
fun main() {
    val arr = intArrayOf(1, 2, 3)
    println(arr.map { it * 2 })
    // 출력: [2, 4, 6]
}
```

> 💡 **눈높이 설명**
>
> Java의 `int[]`와 `Integer[]` 구분이 Kotlin에서는 `IntArray`와 `Array<Int>`로 그대로 남아 있다. 변수의 `Int`는 컴파일러가 알아서 처리해 주지만, 배열은 요소 하나하나가 객체냐 원시값이냐가 성능에 직접 영향을 주기 때문에 개발자가 고른다.

## Java와 비교

| 항목 | Java | Kotlin |
|---|---|---|
| 숫자 타입 | `int` / `Integer` 구분 | `Int` 하나(컴파일러가 선택) |
| null 가능한 숫자 | `Integer` | `Int?` |
| 숫자 타입 변환 | 작은 타입→큰 타입 자동 확장 | 항상 명시적(`toLong()` 등) |
| 최상위 타입 | `Object` (null 가능) | `Any`(non-null), `Any?`(null 포함) |
| 반환값 없음 | `void` (값 없음) | `Unit` (값이 있는 타입) |
| 반환하지 않음 | 표현 수단 없음 | `Nothing` |
| 컬렉션 | 읽기·쓰기가 한 인터페이스 | `List` / `MutableList` 분리 |
| 값 동등 비교 | `equals` | `==` |
| 참조 비교 | `==` | `===` |
| 원시 배열 | `int[]` | `IntArray` |
| 객체 배열 | `String[]` | `Array<String>` |

## 헷갈리기 쉬운 점

- `Int?`는 박싱되므로 `Int`보다 약간 비싸다. 성능이 중요한 루프 변수에는 널 가능 타입을 피한다.
- 숫자 타입은 자동 확장이 없다. `val l: Long = intValue`는 컴파일 오류다.
- `Any`에는 null을 넣을 수 없다. "무엇이든 담는 변수"가 필요하면 `Any?`다.
- `Unit`을 반환하는 함수는 `return`이 없어도 되지만, 제네릭 `T`에 `Unit`이 들어가는 것도 정상이다.
- `List`는 읽기 전용 "뷰"일 뿐 불변 객체가 아니다. 다른 곳에서 같은 객체를 `MutableList`로 들고 있으면 내용이 바뀐다.
- Java에서 온 컬렉션을 `List`로 받아도 원소나 리스트 자체가 null일 수 있다. 플랫폼 타입 경계에서는 `Mutable`/`?` 여부를 직접 결정해야 한다.
- `Array<Int>`와 `IntArray`는 서로 다른 타입이라 호환되지 않는다.

## 스스로 점검

1. Kotlin에서 `Int`는 언제 JVM `int`가 되고 언제 `Integer`가 되는가?

<details>
<summary>답 보기</summary>

일반 변수·프로퍼티·함수 인자에 쓰인 non-null `Int`는 보통 `int`가 된다. `Int?`이거나 제네릭 인자(`List<Int>` 등)처럼 객체여야 하는 자리에서는 `Integer`로 박싱된다.

</details>

2. `Any`와 `Any?`의 차이는? 어느 쪽이 Java의 `Object`와 더 가까운가?

<details>
<summary>답 보기</summary>

`Any`는 null을 담을 수 없는 최상위 타입이고, `Any?`는 null까지 담는다. 모든 참조가 null일 수 있는 Java의 `Object`는 의미상 `Any?`와 더 가깝지만, 멤버를 가진 타입으로는 `Any`와 대응시킨다.

</details>

3. `Unit`과 Java `void`의 차이를 제네릭 관점에서 설명해 보라.

<details>
<summary>답 보기</summary>

`Unit`은 값이 하나뿐인 실제 타입이라 `List<Unit>`, `() -> T`의 `T` 같은 제네릭 자리에 쓸 수 있다. `void`는 타입이 아니라서 `Callable<Void>`처럼 래퍼와 `return null`이 필요하다.

</details>

4. `val n: String = name ?: fail("...")`에서 `fail`의 반환 타입이 `Nothing`이어야 하는 이유는?

<details>
<summary>답 보기</summary>

`Nothing`은 모든 타입의 하위 타입이고 정상 반환하지 않는다. 그래서 `?:` 오른쪽이 `String` 자리에 들어갈 수 있고, 컴파일러는 이 줄을 지난 `n`이 null이 아님을 확신한다.

</details>

5. `List<Int>`로 선언한 변수가 가리키는 리스트의 내용이 바뀔 수 있는 상황은?

<details>
<summary>답 보기</summary>

같은 객체를 `MutableList<Int>` 참조로도 들고 있는 경우다. 또 Java 코드가 그 리스트를 수정하는 경우에도 바뀐다. `List`는 그 참조로 변경할 수 없다는 뜻일 뿐이다.

</details>

6. 정수 수천 개를 담는 배열을 만들 때 `Array<Int>` 대신 `IntArray`를 쓰는 이유는?

<details>
<summary>답 보기</summary>

`Array<Int>`는 `Integer[]`라 요소마다 박싱된 객체가 필요하다. `IntArray`는 `int[]`로 컴파일되어 박싱 비용이 없고 메모리도 적게 쓴다.

</details>
