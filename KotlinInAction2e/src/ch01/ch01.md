# 1장. 코틀린은 무엇이며 왜 필요한가?

## 한눈에 보기

이 장은 "왜 Kotlin을 배워야 하는가?"라는 질문에 답한다. Kotlin은 JVM 위에서 동작하는 정적 타입 언어로, Java와 완전히 호환되면서도 간결한 문법과 안전한 null 처리를 제공한다. Java의 생산성 문제를 해결하면서 기존 Java 코드베이스와 함께 사용할 수 있어, 점진적 마이그레이션이 가능하다.

## 핵심 개념

### Kotlin의 탄생 배경

JetBrains는 IntelliJ IDEA를 비롯한 대규모 Java 코드베이스를 유지보수하면서 Java의 한계를 경험했다. 보일러플레이트 코드가 많고, null 안전성이 없으며, 함수형 프로그래밍 지원이 부족했다. 이런 문제를 해결하면서도 Java와 100% 호환되는 언어가 필요했고, 2011년 Kotlin 프로젝트가 시작되었다.

> 💡 **눈높이 설명**
>
> Java는 하위 호환성을 중시하기 때문에 새로운 기능을 추가할 때 기존 설계의 제약을 받는다. 예를 들어 Java에서 null 안전성을 언어 차원에서 지원하려면 수십 년간 작성된 모든 Java 코드와 호환되어야 하므로 쉽지 않다. Kotlin은 새로운 언어로 시작했기 때문에 처음부터 null 안전성을 설계에 반영할 수 있었다.

### 정적 타입 언어 (Statically Typed Language)

Kotlin은 Java처럼 모든 변수와 함수의 타입이 컴파일 타임에 결정된다. 하지만 Java와 달리 **타입 추론(type inference)** 을 지원하므로 타입을 명시하지 않아도 컴파일러가 자동으로 타입을 알아낸다.

```kotlin
fun main() {
    val name = "Kotlin"  // 컴파일러가 String 타입으로 추론
    val version = 2      // 컴파일러가 Int 타입으로 추론

    println("$name $version")
    // 출력: Kotlin 2
}
```

Java에서는 `String name = "Kotlin";`처럼 타입을 명시해야 하지만, Kotlin은 우변의 값을 보고 타입을 추론한다. 필요한 경우에만 `val name: String = "Kotlin"`처럼 타입을 명시할 수 있다.

### Null 안전성 (Null Safety)

Java에서 `NullPointerException`은 가장 흔한 런타임 오류다. Kotlin은 타입 시스템 수준에서 null 가능성을 구분한다.

```kotlin
fun main() {
    val notNull: String = "Hello"
    // val cannotBeNull: String = null  // 컴파일 에러

    val canBeNull: String? = null  // ? 연산자로 null 허용

    // null 체크 없이 접근하면 컴파일 에러
    // println(canBeNull.length)

    // 안전한 호출 연산자
    println(canBeNull?.length)  // null이면 null 반환
    // 출력: null

    // 엘비스 연산자로 기본값 제공
    println(canBeNull?.length ?: 0)
    // 출력: 0
}
```

> 💡 **눈높이 설명**
>
> Java에서는 모든 참조 타입이 null일 수 있다. `String name;`이 null인지는 런타임에만 알 수 있고, 개발자가 매번 `if (name != null)` 체크를 해야 한다. Kotlin은 `String`과 `String?`을 다른 타입으로 취급해서, null 가능성이 있는 변수는 컴파일러가 강제로 체크하게 만든다. 이렇게 하면 NullPointerException을 컴파일 타임에 대부분 잡아낼 수 있다.

### 함수형 프로그래밍과 객체지향의 결합

Kotlin은 객체지향과 함수형 프로그래밍 스타일을 모두 지원한다. 함수를 변수에 저장하고, 인자로 전달하고, 반환할 수 있다(일급 함수).

```kotlin
fun main() {
    val numbers = listOf(1, 2, 3, 4, 5)

    // 함수형 스타일: 람다를 사용한 컬렉션 처리
    val evenNumbers = numbers.filter { it % 2 == 0 }
    val doubled = evenNumbers.map { it * 2 }

    println(doubled)
    // 출력: [4, 8]

    // 메서드 체이닝으로 간결하게
    val result = numbers
        .filter { it % 2 == 0 }
        .map { it * 2 }

    println(result)
    // 출력: [4, 8]
}
```

Java 8 이후 스트림 API와 비슷하지만, Kotlin은 언어 차원에서 람다를 지원하고 더 간결한 문법을 제공한다.

### Java와의 상호운용성 (Java Interoperability)

Kotlin 코드는 Java 바이트코드로 컴파일되므로 JVM 위에서 실행된다. 따라서 기존 Java 라이브러리와 프레임워크를 그대로 사용할 수 있다.

```kotlin
// Java의 ArrayList를 그대로 사용
import java.util.ArrayList

fun main() {
    val list = ArrayList<String>()
    list.add("Java")
    list.add("Kotlin")

    println(list)
    // 출력: [Java, Kotlin]
}
```

반대로 Java 코드에서도 Kotlin 코드를 호출할 수 있다. 이 덕분에 기존 Java 프로젝트에서 일부 파일만 Kotlin으로 바꾸는 점진적 마이그레이션이 가능하다.

### 간결한 문법

Java에서 반복적으로 작성해야 하는 코드(보일러플레이트)를 Kotlin은 줄여준다.

**Java:**
```java
public class Person {
    private final String name;
    private int age;

    public Person(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public String getName() { return name; }
    public int getAge() { return age; }
    public void setAge(int age) { this.age = age; }
}
```

**Kotlin:**
```kotlin
data class Person(val name: String, var age: Int)

fun main() {
    val person = Person("Alice", 29)
    println(person.name)  // getter 자동 생성
    person.age = 30       // setter 자동 생성
    println(person)       // toString() 자동 생성
    // 출력: Person(name=Alice, age=30)
}
```

`data class` 키워드 하나로 생성자, getter, setter, `equals()`, `hashCode()`, `toString()`, `copy()` 메서드가 모두 자동 생성된다.

### Kotlin이 쓰이는 곳

- **서버 사이드**: Spring, Ktor 등의 프레임워크에서 Java 대신 사용
- **안드로이드**: 2019년 구글이 Kotlin을 안드로이드 공식 언어로 지정
- **멀티플랫폼**: Kotlin Multiplatform을 사용해 JVM, JavaScript, Native(iOS, 데스크톱) 코드를 공유

## Java와 비교

| 항목 | Java | Kotlin |
|------|------|--------|
| Null 안전성 | 모든 참조 타입이 null 가능, 런타임 체크 필요 | `String`과 `String?`로 구분, 컴파일 타임 체크 |
| 타입 선언 | 명시적 (`String name = "..."`) | 타입 추론 지원 (`val name = "..."`) |
| 클래스 작성 | 생성자, getter, setter 등 수동 작성 | `data class`로 자동 생성 |
| 함수형 지원 | Java 8부터 람다와 스트림 추가 | 언어 설계부터 함수형 지원, 더 간결한 문법 |
| 상호운용성 | - | Java 라이브러리 사용 가능, Java에서 Kotlin 호출 가능 |

## 헷갈리기 쉬운 점

### "Kotlin을 배우면 Java를 버려야 하나?"

아니다. Kotlin은 Java를 대체하는 것이 아니라 **보완**한다. 같은 프로젝트 안에서 Java 파일과 Kotlin 파일이 공존할 수 있고, 서로 자유롭게 호출할 수 있다. 기존 Java 프로젝트에서 새로운 기능만 Kotlin으로 작성하거나, 불편한 부분만 점진적으로 변환하는 방식으로 도입할 수 있다.

### "함수형 프로그래밍을 모르면 Kotlin을 쓸 수 없나?"

Kotlin은 함수형 스타일을 **지원**하지만 **강제하지 않는다**. Java처럼 객체지향 스타일로만 작성해도 된다. 다만 컬렉션 처리 같은 곳에서 `filter`, `map` 같은 함수형 API를 사용하면 코드가 훨씬 간결해지므로, 필요할 때 조금씩 배워서 적용하면 된다.

### "타입 추론이 있으면 타입을 몰라도 되나?"

타입 추론은 **타입 선언을 생략**할 수 있게 해 주는 것이지, 타입이 없다는 뜻이 아니다. 컴파일러는 여전히 모든 변수의 타입을 알고 있고, 타입이 맞지 않으면 컴파일 에러를 낸다. JavaScript나 Python 같은 동적 타입 언어와는 다르다.

```kotlin
fun main() {
    val number = 10        // Int로 추론
    // val result = number + "text"  // 컴파일 에러: 타입 불일치
}
```

## 스스로 점검

<details>
<summary>1. Kotlin이 Java와 100% 호환된다는 말의 의미는 무엇인가?</summary>

Kotlin 코드는 Java 바이트코드로 컴파일되어 JVM에서 실행된다. 따라서 Kotlin에서 Java 라이브러리를 사용할 수 있고, Java 코드에서 Kotlin 코드를 호출할 수 있다. 같은 프로젝트 안에서 Java와 Kotlin 파일이 공존하며 서로 호출할 수 있다는 뜻이다.
</details>

<details>
<summary>2. `String`과 `String?` 타입의 차이는 무엇인가?</summary>

`String`은 null이 될 수 없는 타입이고, `String?`은 null이 될 수 있는 타입이다. `String` 타입 변수에는 null을 대입할 수 없으며, 컴파일러가 이를 체크한다. `String?` 타입 변수는 null을 가질 수 있지만, 사용하기 전에 null 체크를 해야 한다.
</details>

<details>
<summary>3. Kotlin의 `data class`가 자동으로 생성해 주는 메서드는 무엇인가?</summary>

생성자 파라미터에 대한 getter (val인 경우) / getter와 setter (var인 경우), `equals()`, `hashCode()`, `toString()`, `copy()` 메서드를 자동으로 생성한다.
</details>

<details>
<summary>4. Java 프로젝트를 Kotlin으로 바꾸려면 모든 파일을 한 번에 변환해야 하나?</summary>

아니다. Java와 Kotlin은 같은 프로젝트에서 공존할 수 있으므로, 파일 하나씩 점진적으로 변환하거나 새로운 기능만 Kotlin으로 작성하는 방식으로 도입할 수 있다.
</details>

<details>
<summary>5. 타입 추론이 있으면 Kotlin은 동적 타입 언어인가?</summary>

아니다. Kotlin은 정적 타입 언어다. 타입 추론은 단지 개발자가 타입을 명시하지 않아도 컴파일러가 타입을 알아내는 기능일 뿐, 모든 타입은 컴파일 타임에 결정되고 타입 검사가 이루어진다.
</details>
