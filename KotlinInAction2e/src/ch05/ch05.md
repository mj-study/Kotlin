# 5장. 람다를 사용한 프로그래밍

## 한눈에 보기

이 장은 "Java의 람다/메서드 참조/함수형 인터페이스 감각을 Kotlin에서는 어떻게 쓰고, 수신 객체 지정 람다는 무엇이 새로운가?"에 답한다.

- 람다(lambda)는 `{ 파라미터 -> 본문 }` 형태이고, 본문의 **마지막 식**이 반환값이다.
- 멤버 참조(member reference) `::`로 이미 있는 함수/프로퍼티를 람다처럼 넘긴다.
- Java 함수형 인터페이스(SAM)를 받는 곳에는 람다를 바로 넘길 수 있다. 명시적 변환이 필요하면 SAM 생성자를 쓴다.
- Kotlin 쪽에서 SAM 인터페이스를 만들려면 `fun interface`로 선언한다.
- 수신 객체 지정 람다(lambda with receiver)는 람다 안에서 `this`를 특정 객체로 바꾸는 기능이고, `with`/`apply`/`also`가 그 대표 도구다.

## 핵심 개념

### 람다 소개

람다는 "코드 블록을 값처럼 넘기는" 문법이다. 컬렉션 함수형 API(`filter`, `map` 등)의 구체적인 활용은 다음 장에서 이어지므로 여기서는 문법과 규칙만 본다.

```kotlin
fun main() {
    val sum = { x: Int, y: Int -> x + y }     // 타입: (Int, Int) -> Int
    println(sum(1, 2))

    val names = listOf("kim", "lee", "park")
    println(names.maxByOrNull { it.length })  // 후행 람다 + it
    // 출력:
    // 3
    // park
}
```

- **후행 람다(trailing lambda)**: 마지막 인자가 람다면 괄호 밖으로 뺄 수 있다. 람다가 유일한 인자면 `()`도 생략한다.
- **`it`**: 파라미터가 하나면 이름을 생략하고 `it`으로 쓸 수 있다.
- 본문이 여러 줄이면 마지막 식이 결과다. `return`을 쓰지 않는다.

**Java와 비교:** Java는 `(x, y) -> x + y`, 본문이 블록이면 `return` 필수. Kotlin은 `{ x, y -> x + y }`.

변수 캡처(capture)에도 차이가 있다.

```kotlin
fun main() {
    var count = 0
    listOf(1, 2, 3).forEach { count += it }   // 바깥 var을 수정
    println(count)
    // 출력: 6
}
```

> 💡 **눈높이 설명**
>
> Java 람다는 바깥 지역 변수를 읽기만 할 수 있다(effectively final). Kotlin 람다는 `var`도 읽고 **쓸 수** 있다. 내부적으로는 그 변수를 `Ref` 같은 래퍼 객체에 담아 람다와 공유하기 때문이다. 다만 람다가 비동기로 나중에 실행되는 경우, 변수 변경 시점을 직접 신경 써야 한다.

### 멤버 참조

`클래스::멤버` 형태로, 이미 있는 함수나 프로퍼티를 람다 대신 넘긴다. 시그니처가 맞아야 한다.

```kotlin
data class Person(val name: String, val age: Int)

fun isAdult(p: Person) = p.age >= 20

fun main() {
    val people = listOf(Person("kim", 30), Person("lee", 15))
    println(people.map(Person::name))          // 프로퍼티 참조
    println(people.filter(::isAdult))          // 최상위 함수 참조
    val make = ::Person                        // 생성자 참조
    println(make("park", 40))
    val bound = people[0]::name                // 바운드 참조
    println(bound())
    // 출력:
    // [kim, lee]
    // [Person(name=kim, age=30)]
    // Person(name=park, age=40)
    // kim
}
```

| 형태 | 의미 | Java |
|---|---|---|
| `Person::name` | 클래스의 멤버 | `Person::getName` |
| `::isAdult` | 최상위 함수(클래스명 생략) | 해당 없음 |
| `::Person` | 생성자 | `Person::new` |
| `obj::name` | 특정 인스턴스에 묶은 참조(bound) | `obj::getName` |

> 💡 **눈높이 설명**
>
> `Person::name`은 getter 호출 `Person::getName`이 아니라 프로퍼티 자체를 가리키는 참조다. 결과적으로 `(Person) -> String`처럼 쓸 수 있다. `::isAdult`처럼 앞의 클래스 이름이 비는 것은 최상위 함수가 어느 클래스에도 속하지 않기 때문이다.

### SAM 변환

SAM(Single Abstract Method) 인터페이스는 추상 메서드가 하나인 인터페이스(Java의 함수형 인터페이스)다. **Java 메서드가 SAM 인터페이스를 인자로 받으면 Kotlin 람다를 그대로 넘길 수 있다.** 컴파일러가 자동으로 변환(SAM 변환)한다.

```kotlin
fun main() {
    val t = Thread { println("run in thread") }   // Runnable을 람다로
    t.start()
    t.join()
    // 출력: run in thread
}
```

#### SAM 생성자란?

SAM 생성자는 **람다를 함수형 인터페이스 인스턴스로 명시적으로 바꾸는** 함수다. 인터페이스 이름 뒤에 `{ ... }`를 붙이는 형태이고, 인터페이스마다 컴파일러가 자동으로 만들어 준다.

```kotlin
fun main() {
    val task: Runnable = Runnable { println("task") }  // SAM 생성자
    task.run()
    task.run()
    // 출력:
    // task
    // task
}
```

자동 변환이 안 되는 곳(반환값으로 돌려줄 때, 변수에 담을 때)에 쓴다.

```kotlin
fun createComparator() = Comparator<String> { a, b -> a.length - b.length }

fun main() {
    println(listOf("ccc", "a", "bb").sortedWith(createComparator()))
    // 출력: [a, bb, ccc]
}
```

> 💡 **눈높이 설명**
>
> Java 람다는 대입되는 자리의 타입(target type)에 따라 인터페이스로 해석된다. Kotlin 람다는 `(A) -> B` 함수 타입일 뿐 인터페이스가 아니다. 그래서 Java 메서드의 인자처럼 변환 대상이 분명한 자리에서만 자동 변환되고, 반환값이나 변수처럼 문맥이 없는 자리에서는 SAM 생성자로 "이건 Runnable이야"라고 알려 줘야 한다. 리스너를 등록했다가 해제해야 한다면 같은 인스턴스가 필요하므로 변수에 담아 두고 쓴다.

### SAM 인터페이스 정의

Kotlin에서 직접 만든 인터페이스를 람다로 구현하려면 `fun interface`로 선언한다. 추상 메서드가 정확히 하나여야 한다.

```kotlin
fun interface Validator {
    fun validate(input: String): Boolean
}

fun check(s: String, v: Validator) = v.validate(s)

fun main() {
    println(check("hi", { it.isNotBlank() }))
    val notEmpty = Validator { it.isNotEmpty() }
    println(notEmpty.validate(""))
    // 출력:
    // true
    // false
}
```

> 💡 **눈높이 설명**
>
> Kotlin 함수의 파라미터가 `(String) -> Boolean` 같은 **함수 타입**이면 람다를 그냥 넘기면 되고 SAM 변환은 필요 없다. `fun interface`는 (1) 이름 붙은 타입으로 의미를 드러내고 싶거나 (2) Java 쪽과 인터페이스로 주고받아야 할 때 쓴다. `fun`이 없는 일반 Kotlin `interface`는 SAM 변환이 안 된다.

### 수신 객체 지정 람다

일반 람다 `(T) -> R`과 달리 **수신 객체 지정 람다는 `T.() -> R`** 타입이다. 람다 안에서 `T` 객체가 `this`가 되어, 접근자 없이 `T`의 멤버를 바로 부를 수 있다. 확장 함수 본문과 같은 감각이다.

```kotlin
fun buildMessage(block: StringBuilder.() -> Unit): String {
    val sb = StringBuilder()
    sb.block()                // 수신 객체를 sb로 지정해 실행
    return sb.toString()
}

fun main() {
    val msg = buildMessage {
        append("Hello")       // this.append 생략
        append(", Kotlin")
    }
    println(msg)
    // 출력: Hello, Kotlin
}
```

표준 라이브러리의 `buildString { ... }`가 이 방식이다. 이 개념이 DSL(domain-specific language)의 기반이며, 본격적인 DSL은 뒤에서 다룬다.

> 💡 **눈높이 설명**
>
> Java에는 대응 개념이 없다. 람다 안의 `this`는 보통 바깥 클래스 인스턴스를 뜻한다. 수신 객체 지정 람다에서는 `this`가 **호출 쪽이 정해 준 객체**로 바뀐다. 코드를 읽을 때 "이 `append`는 누구의 `append`지?"를 람다의 타입(`StringBuilder.() -> Unit`)에서 찾아야 한다.

### with, apply, also

모두 표준 라이브러리의 범위 지정 함수(scope function)다. 차이는 **(1) 수신 객체를 `this`로 받는가 `it`으로 받는가, (2) 무엇을 반환하는가**다.

| 함수 | 호출 형태 | 람다 안 | 반환값 |
|---|---|---|---|
| `with` | `with(obj) { }` | `this` | 람다의 마지막 식 |
| `apply` | `obj.apply { }` | `this` | 수신 객체 `obj` |
| `also` | `obj.also { }` | `it` | 수신 객체 `obj` |

#### with — 마지막 식을 반환

```kotlin
fun main() {
    val sb = StringBuilder("abc")
    val len = with(sb) {
        append("def")
        length                // 마지막 식이 반환값
    }
    println(len)
    // 출력: 6
}
```

`with`는 확장 함수가 아니라 **일반 함수**라서 `with(obj) { }`처럼 객체를 인자로 받는다. "이 객체로 이것저것 하고 결과를 계산"할 때 쓴다.

#### apply — 수신 객체를 반환

```kotlin
class Config { var host = ""; var port = 0 }

fun main() {
    val c = Config().apply {
        host = "localhost"    // this.host
        port = 8080
    }
    println("${c.host}:${c.port}")
    // 출력: localhost:8080
}
```

객체 생성과 초기화를 한 식으로 묶을 때 쓴다. 반환값이 객체 자신이라서 체이닝하거나 변수에 바로 대입하기 좋다.

#### also — apply와 무엇이 다른가

`also`도 수신 객체를 반환하지만, **람다 안에서 수신 객체를 `this`가 아니라 `it`(또는 이름 붙인 파라미터)으로 받는다.** 반환값은 같고, 람다 안의 접근 방식만 다르다.

```kotlin
class Box { var value = 0 }

fun main() {
    val box = Box().also { b ->
        println("created: ${b.value}")   // 부수 효과(로깅)
        b.value = 5
    }
    val b2 = Box().apply {
        value = 5                        // this 생략
    }
    println("${box.value} ${b2.value}")
    // 출력:
    // created: 0
    // 5 5
}
```

| 구분 | `apply` | `also` |
|---|---|---|
| 하는 일 | 객체 **설정/초기화** | 객체를 건드리지 않는 **부수 효과**(로깅, 검증) |
| 객체 접근 | `this` (생략 가능) | `it` / 명시한 이름 |
| 이름 충돌 | 바깥 같은 이름 멤버와 헷갈릴 수 있음 | 이름이 명시되므로 안전 |
| 반환 | 수신 객체 | 수신 객체 |

> 💡 **눈높이 설명**
>
> 쉽게 구분하려면 이렇게 생각하면 된다. 객체 **내부 상태를 채우고 있다**면 `apply`, 객체를 **밖에서 구경하며 뭔가 하고 있다**면 `also`다. `apply` 안에서는 `this`가 바뀌므로, 바깥 클래스의 멤버와 이름이 겹치면 어느 쪽인지 헷갈린다. `also`는 `it`이라는 이름을 달아 그 혼동을 피한다.

## Java와 비교

| 항목 | Java | Kotlin |
|---|---|---|
| 람다 문법 | `(x, y) -> x + y` | `{ x, y -> x + y }` |
| 본문 반환 | `return` 필요(블록일 때) | 마지막 식이 결과 |
| 파라미터 하나 | 이름 지정 필요 | `it` 사용 가능 |
| 마지막 인자 람다 | 괄호 안 | 괄호 밖으로 뺄 수 있음(후행 람다) |
| 바깥 변수 캡처 | effectively final만 읽기 | `var`도 읽기/쓰기 |
| 메서드 참조 | `Person::getName`, `Person::new` | `Person::name`, `::Person` |
| 함수형 인터페이스 선언 | `@FunctionalInterface` (선택) | `fun interface` |
| 람다 → 인터페이스 명시 변환 | 타입 문맥으로 추론 | SAM 생성자 `Runnable { }` |
| 람다 안의 `this` | 바깥 클래스 | 일반 람다는 바깥, 수신 객체 지정 람다는 수신 객체 |
| 범위 지정 함수 | 없음 | `with`, `apply`, `also` 등 |

## 헷갈리기 쉬운 점

- **`apply`와 `also` 반환값을 다르게 착각**: 둘 다 수신 객체를 반환한다. 다른 것은 람다 안의 `this`/`it`뿐이다.
- **`with`와 `apply` 반환값 혼동**: `with`는 마지막 식, `apply`는 수신 객체다. `with` 안에서 마지막 줄이 대입문이면 값이 되지 않아 컴파일 에러가 난다.
- **`it`/`this` 혼동**: `also`에서 `this`를 쓰면 바깥 클래스 인스턴스다. `apply`에서 `it`을 쓰면 컴파일 에러다.
- **멤버 참조 생략 형태**: `::isAdult`처럼 클래스 이름을 생략하는 건 최상위 함수만 해당한다. 멤버 함수는 `Person::name`처럼 클래스가 필요하다.
- **일반 Kotlin `interface`에 람다를 넘김**: `fun`이 없으면 SAM 변환이 안 된다. 함수 타입 파라미터를 쓰거나 `fun interface`로 바꾼다.
- **람다의 `return`**: 람다 안 `return`은 바깥 함수까지 빠져나가는 비지역 반환이 될 수 있다. 라벨 `return@forEach`로 람다만 종료한다(자세한 조건은 인라인 함수에서 다룸).

## 스스로 점검

1. `{ x: Int -> x * 2 }`의 타입은 무엇이고, 마지막 인자로 쓸 때 어떻게 줄여 쓸 수 있는가?

<details>
<summary>답</summary>

타입은 `(Int) -> Int`다. 마지막 인자면 괄호 밖으로 뺄 수 있고(후행 람다), 파라미터가 하나이므로 `{ it * 2 }`로 줄일 수 있다.

</details>

2. SAM 생성자는 언제 필요한가? 예를 들어 설명하라.

<details>
<summary>답</summary>

자동 SAM 변환이 일어나지 않는 곳, 즉 람다를 함수형 인터페이스 값으로 반환하거나 변수에 담아야 할 때 필요하다. 예: `val r = Runnable { println("hi") }`, `Comparator<String> { a, b -> ... }`.

</details>

3. 직접 만든 Kotlin 인터페이스를 람다로 구현하려면 무엇을 해야 하는가?

<details>
<summary>답</summary>

인터페이스 선언 앞에 `fun`을 붙여 `fun interface`로 만들고, 추상 메서드를 정확히 하나만 둔다.

</details>

4. `StringBuilder.() -> Unit` 타입의 람다에서 `append("x")`를 접두사 없이 호출할 수 있는 이유는?

<details>
<summary>답</summary>

수신 객체 지정 람다에서는 `StringBuilder` 인스턴스가 람다 안의 `this`가 되기 때문이다. `this.append("x")`에서 `this`가 생략된 것이다.

</details>

5. `with`, `apply`, `also`를 반환값과 람다 안의 수신 객체 표기로 구분하라.

<details>
<summary>답</summary>

`with`: `this`, 마지막 식 반환. `apply`: `this`, 수신 객체 반환. `also`: `it`, 수신 객체 반환.

</details>
