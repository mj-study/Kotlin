# 3장. 함수 정의와 호출

## 한눈에 보기

이 장은 "Java 코드를 Kotlin에서 더 편하게 호출하고, 함수를 더 편하게 정의하려면 어떻게 하는가?"에 답한다.

- 컬렉션(collection)은 Java 클래스를 그대로 쓰되, 확장 함수(extension function)로 기능을 덧붙인 형태다.
- 이름 붙인 인자(named argument)와 디폴트 파라미터 값(default parameter value)으로 오버로드(overload) 폭발을 줄인다.
- 최상위 함수(top-level function)와 프로퍼티 덕분에 `Utils` 같은 정적 유틸 클래스가 필요 없다.
- 확장 함수로 기존 클래스(예: `String`)에 메서드를 "추가한 것처럼" 쓸 수 있다. 단, 실제로 클래스를 수정하는 것은 아니다.
- 로컬 함수(local function)로 반복 코드를 함수 안에서 정리한다.

## 핵심 개념

### 코틀린에서 컬렉션 만들기

Kotlin은 자체 컬렉션 클래스를 새로 만들지 않고 Java 표준 컬렉션(`ArrayList`, `HashMap` 등)을 그대로 사용한다. 대신 생성을 돕는 `setOf`, `listOf`, `mapOf` 같은 함수를 제공한다.

```kotlin
fun main() {
    val set = setOf(1, 7, 53)
    val list = listOf("a", "b", "c")
    val map = mapOf(1 to "one", 7 to "seven")

    println(set.javaClass)
    println(list.last())
    println(map[7])
    // 출력:
    // class java.util.LinkedHashSet
    // c
    // seven
}
```

**Java와 비교:**
- Java: `List.of("a", "b", "c")`, `map.get(7)`
- Kotlin: `listOf("a", "b", "c")`, `map[7]`

> 💡 **눈높이 설명**
>
> 런타임 객체는 Java 컬렉션이라서 Java 코드와 주고받을 때 변환 비용이 없다. 다만 `last()`, `max()` 같은 메서드는 `java.util.List`에 원래 없는 것이다. Kotlin이 확장 함수로 붙여 준 것이다. 컬렉션의 읽기 전용/변경 가능 구분은 이 책의 다른 장에서 더 다룬다.

`1 to "one"`은 `Pair`를 만드는 `to` 함수 호출이다(뒤의 중위 호출 참고).

### 함수를 호출하기 쉽게 만들기

컬렉션의 기본 `toString()`은 `[1, 2, 3]` 형태다. 구분자와 접두/접미사를 바꾸는 함수를 직접 만들면서 아래 기능들을 본다.

```kotlin
fun <T> joinToString(
    collection: Collection<T>,
    separator: String,
    prefix: String,
    postfix: String,
): String {
    val sb = StringBuilder(prefix)
    for ((index, element) in collection.withIndex()) {
        if (index > 0) sb.append(separator)
        sb.append(element)
    }
    return sb.append(postfix).toString()
}

fun main() {
    println(joinToString(listOf(1, 2, 3), "; ", "(", ")"))
    // 출력: (1; 2; 3)
}
```

위 호출은 인자 네 개의 의미가 한눈에 안 들어온다. 이를 개선하는 방법이 다음 두 가지다.

#### 이름 붙인 인자

호출할 때 파라미터 이름을 명시한다. 이름을 붙이면 순서가 달라도 된다.

```kotlin
fun describe(name: String, age: Int, city: String) = "$name($age, $city)"

fun main() {
    println(describe(name = "민준", age = 30, city = "서울"))
    println(describe(city = "부산", name = "수아", age = 25))
    // 출력:
    // 민준(30, 서울)
    // 수아(25, 부산)
}
```

> 💡 **눈높이 설명**
>
> Java에는 인자 이름을 호출부에 쓰는 문법이 없어서, 주석이나 IDE 힌트에 의존한다. Kotlin의 이름 붙인 인자는 컴파일러가 검사하는 "주석"이다. 함수 파라미터 이름을 바꾸면 호출부가 컴파일 에러가 되므로, 이름 변경이 호출자에게 영향을 준다는 점을 기억해야 한다. 또한 이 문법은 Kotlin 함수에만 쓸 수 있고 Java 메서드를 호출할 때는 쓸 수 없다.

#### 디폴트 파라미터 값

파라미터에 기본값을 지정하면 호출할 때 생략할 수 있다.

```kotlin
fun greet(name: String, greeting: String = "안녕", punct: String = "!") =
    "$greeting, $name$punct"

fun main() {
    println(greet("지민"))
    println(greet("지민", punct = "?"))
    println(greet("지민", "Hello"))
    // 출력:
    // 안녕, 지민!
    // 안녕, 지민?
    // Hello, 지민!
}
```

**Java와 비교:**

```java
// Java: 조합마다 오버로드를 직접 만들어야 한다
String greet(String name) { return greet(name, "안녕", "!"); }
String greet(String name, String greeting) { return greet(name, greeting, "!"); }
String greet(String name, String greeting, String punct) { ... }
```

> 💡 **눈높이 설명**
>
> 기본값은 함수를 **호출하는 쪽**에서 채워진다. Java에서 이런 Kotlin 함수를 호출하면 기본값이 적용되지 않으므로 모든 인자를 넘겨야 한다. Java 호출자도 오버로드를 쓰게 하려면 `@JvmOverloads` 애노테이션을 붙인다(확인 필요 참고).

### 최상위 함수와 프로퍼티

Kotlin은 클래스 밖, 파일 최상위에 함수와 프로퍼티를 선언할 수 있다. Java의 `static` 유틸 클래스를 대체한다.

```kotlin
package strings

const val UNIX_LINE_SEPARATOR = "\n"   // 최상위 상수

fun lastChar(s: String): Char = s[s.length - 1]

fun main() {
    println(lastChar("Kotlin"))
    println(UNIX_LINE_SEPARATOR == "\n")
    // 출력:
    // n
    // true
}
```

**Java와 비교:**
- Java: `StringUtils.lastChar(s)` 처럼 클래스 이름을 거쳐 호출
- Kotlin: 같은 패키지면 `lastChar(s)`, 다른 패키지면 `import strings.lastChar`

> 💡 **눈높이 설명**
>
> 컴파일하면 최상위 함수는 파일 이름 기반 클래스(예: `Strings.kt` → `StringsKt`)의 static 메서드가 된다. Java에서는 그 이름으로 호출한다. 클래스 이름을 바꾸고 싶으면 파일 맨 위에 `@file:JvmName("...")`을 쓴다. 최상위 프로퍼티는 기본적으로 getter를 통해 노출되고, `const val`이면 상수 필드가 된다.

### 확장 함수

기존 클래스에 메서드를 추가한 것처럼 호출하는 함수다. `수신 객체 타입.함수이름` 형태로 선언한다.

```kotlin
fun String.lastChar(): Char = this[this.length - 1]

fun main() {
    println("Kotlin".lastChar())
    // 출력: n
}
```

- `String`: **수신 객체 타입**(receiver type), 확장 대상 클래스
- `this`: **수신 객체**(receiver object), 호출된 인스턴스. 생략도 가능하다(`this[length - 1]`)

**Java와 비교:** Java에서는 `StringUtils.lastChar(s)` 같은 정적 메서드로 쓰던 것을, 인스턴스 메서드처럼 `s.lastChar()`로 호출한다.

> 💡 **눈높이 설명**
>
> 확장 함수는 겉보기만 멤버 메서드이고, 실체는 첫 번째 인자로 수신 객체를 받는 **정적 메서드**다. 그래서 두 가지 제약이 따라온다. 첫째, 클래스의 `private`/`protected` 멤버에는 접근할 수 없다. 둘째, 오버라이드되지 않고, 호출될 함수가 변수의 **선언 타입**으로 결정된다(정적 디스패치). 같은 시그니처의 멤버 메서드가 있으면 멤버가 항상 우선한다.

다른 파일에서 쓰려면 `import`가 필요하고, 이름이 충돌하면 `import ... as ...`로 별칭을 줄 수 있다.

```kotlin
open class Animal
class Dog : Animal()

fun Animal.sound() = "..."
fun Dog.sound() = "멍"

fun main() {
    val a: Animal = Dog()
    println(a.sound())
    println(Dog().sound())
    // 출력:
    // ...
    // 멍
}
```

위 예제처럼 객체는 `Dog`지만 변수 타입이 `Animal`이면 `Animal.sound()`가 호출된다.

#### 확장으로 joinToString 개선하기

앞의 `joinToString`을 `Collection<T>`의 확장 함수로 만들고 기본값을 넣으면 사용성이 좋아진다.

```kotlin
fun <T> Collection<T>.joinToString(
    separator: String = ", ",
    prefix: String = "",
    postfix: String = "",
): String {
    val sb = StringBuilder(prefix)
    for ((i, e) in withIndex()) {
        if (i > 0) sb.append(separator)
        sb.append(e)
    }
    return sb.append(postfix).toString()
}

fun main() {
    println(listOf(1, 2, 3).joinToString(separator = "|", prefix = "<", postfix = ">"))
    // 출력: <1|2|3>
}
```

표준 라이브러리에도 비슷한 `joinToString`이 이미 있으므로 실제로는 직접 만들 필요가 없다.

### 확장 프로퍼티

함수처럼 프로퍼티도 확장할 수 있다. 단, 실제 필드가 없으므로 **getter를 반드시 직접 정의**해야 한다(초기화 불가).

```kotlin
val String.lastIndexValue: Char
    get() = this[length - 1]

var StringBuilder.lastChar: Char
    get() = this[length - 1]
    set(value) { this.setCharAt(length - 1, value) }

fun main() {
    println("abc".lastIndexValue)
    val sb = StringBuilder("abc")
    sb.lastChar = 'Z'
    println(sb)
    // 출력:
    // c
    // abZ
}
```

### 가변 인자와 spread 연산자

`vararg` 키워드로 인자 개수를 가변으로 받는다. 배열을 넘기려면 `*`(spread 연산자)로 펼친다.

```kotlin
fun sum(vararg nums: Int): Int = nums.sum()

fun main() {
    val arr = intArrayOf(4, 5)
    println(sum(1, 2, 3))
    println(sum(1, *arr, 6))
    // 출력:
    // 6
    // 16
}
```

> 💡 **눈높이 설명**
>
> Java는 `int...` 파라미터에 배열을 그대로 넘기면 되지만, Kotlin은 배열을 넘기려면 반드시 `*`로 펼쳐야 한다. 또 `*`를 쓰면 다른 인자와 섞어 쓸 수 있다(`1, *arr, 6`). 함수 안에서 `nums`의 타입은 `IntArray`다.

### 중위 호출과 구조 분해 선언

인자가 하나인 메서드/확장 함수는 `infix`를 붙이면 `.`과 `()` 없이 `a 함수 b`로 호출할 수 있다. `to`가 대표 예시다.

```kotlin
infix fun Int.times2(other: Int) = this * other * 2

fun main() {
    println(3 times2 4)
    val pair = 1 to "one"
    val (num, word) = pair      // 구조 분해 선언
    println("$num / $word")
    // 출력:
    // 24
    // 1 / one
}
```

구조 분해 선언(destructuring declaration)은 `Pair`나 `data class` 같은 객체를 풀어서 여러 변수에 한 번에 담는 문법이다. 컬렉션을 순회하며 `for ((index, element) in list.withIndex())`처럼 쓰는 경우가 많다. 동작 원리는 클래스를 다루는 장에서 나온다.

### 문자열과 정규식 다루기

Kotlin 문자열은 Java의 `String`이지만, 확장 함수로 더 안전하고 편하게 쓸 수 있다.

```kotlin
fun main() {
    println("12.345-6.A".split("."))          // 문자열 구분자
    println("12.345-6.A".split(".", "-"))     // 여러 구분자
    println("12.345-6.A".split("\\.|-".toRegex()))   // 정규식
    // 출력:
    // [12, 345-6, A]
    // [12, 345, 6, A]
    // [12, 345, 6, A]
}
```

**Java와 비교:**
- Java의 `"a.b".split(".")`는 인자를 **정규식**으로 해석해서 의도와 다르게 동작한다.
- Kotlin의 `split(".")`는 문자열 그대로 구분하고, 정규식은 `toRegex()`로 명시한다.

#### 3중 따옴표 문자열

`"""..."""`로 이스케이프 없이 여러 줄 문자열을 쓸 수 있다. 정규식과 잘 어울린다.

```kotlin
fun main() {
    val path = "/Users/jun/Kotlin/ch03.md"
    val regex = """(.+)/(.+)\.(.+)""".toRegex()
    val match = regex.matchEntire(path)
    if (match != null) {
        val (dir, name, ext) = match.destructured
        println("$dir | $name | $ext")
    }
    // 출력: /Users/jun/Kotlin | ch03 | md
}
```

> 💡 **눈높이 설명**
>
> 3중 따옴표 안에서는 `\`도 그냥 문자다. Java라면 정규식 `\.`을 `"\\."`로 써야 했지만 여기서는 `\.` 그대로 쓴다. 대신 `\n` 같은 이스케이프도 동작하지 않는다. 그리고 `$`로 시작하는 템플릿은 여전히 적용된다. 여러 줄 문자열에서 줄마다 들여쓰기가 포함되므로 필요하면 `trimIndent()`로 정리한다.

### 로컬 함수와 확장

함수 안에 함수를 선언해, 중복 코드를 한곳에 모을 수 있다. 로컬 함수는 바깥 함수의 파라미터와 변수에 접근할 수 있다.

```kotlin
class User(val id: Int, val name: String, val address: String)

fun saveUser(user: User) {
    fun validate(value: String, fieldName: String) {
        require(value.isNotEmpty()) {
            "${user.id}번 사용자의 $fieldName 이(가) 비어 있음"
        }
    }
    validate(user.name, "이름")
    validate(user.address, "주소")
    println("저장 완료: ${user.name}")
}

fun main() {
    saveUser(User(1, "민준", "서울"))
    // 출력: 저장 완료: 민준
}
```

검증 로직이 커지면 `User.validateBeforeSave()` 같은 **확장 함수**로 빼내, 로컬 함수 사용을 줄이는 방법도 있다. 이렇게 하면 `User` 클래스는 깔끔하게 유지하면서 저장 시점에만 필요한 로직을 가까이 둘 수 있다.

## Java와 비교

| 항목 | Java | Kotlin |
| --- | --- | --- |
| 컬렉션 생성 | `List.of(...)`, `new HashMap<>()` | `listOf(...)`, `mapOf(k to v)` |
| 컬렉션 클래스 | `java.util.*` | 동일한 `java.util.*` + 확장 함수 |
| 인자 지정 | 순서로만 구분 | `name = value` 이름 붙인 인자 |
| 기본값 | 오버로드 여러 개 | 디폴트 파라미터 값 |
| 유틸 함수 | `static` 메서드가 든 유틸 클래스 | 최상위 함수 |
| 기존 클래스 기능 추가 | 상속 또는 `XxxUtils.method(x)` | 확장 함수 `x.method()` |
| 가변 인자 | `T...`, 배열 그대로 전달 | `vararg`, 배열은 `*` 로 펼침 |
| 문자열 `split(".")` | 정규식으로 해석 | 문자열 그대로 해석 |
| 정규식 문자열 | `"\\d+"` | `"""\d+"""` |
| 함수 안의 함수 | 불가(람다/내부 클래스 대체) | 로컬 함수 |

## 헷갈리기 쉬운 점

- **확장 함수는 다형성이 없다.** 변수의 선언 타입으로 호출이 결정되므로, 하위 타입에서 같은 이름으로 확장해도 오버라이드가 아니다.
- **멤버가 확장보다 우선한다.** 클래스에 같은 시그니처의 메서드가 이미 있으면 확장 함수는 호출되지 않는다.
- **확장 함수는 private 멤버에 접근할 수 없다.** 외부 정적 함수와 같은 위치에 있기 때문이다.
- **확장 프로퍼티는 필드가 없다.** 값을 저장할 수 없고, getter(와 setter)만 정의할 수 있다.
- **디폴트 값은 Java 호출자에게 보이지 않는다.** Java에서 호출할 계획이면 `@JvmOverloads`가 필요하다.
- **배열 인자는 `*`를 빠뜨리면 안 된다.** `sum(arr)`는 컴파일 에러다(`vararg Int`에 `IntArray`를 넘긴 것).
- **`split(".")`의 결과가 Java와 다르다.** Java는 정규식 때문에 빈 배열이 나오기도 한다.

   ```kotlin
   open class A
   class B : A()
   fun A.hi() = "A"
   fun B.hi() = "B"
   fun main() { val x: A = B(); println(x.hi()) }
   ```

   <details>
   <summary>답</summary>

   `A`가 출력된다. 확장 함수는 정적으로 결정되어 변수의 선언 타입(`A`)을 따르며, 실제 객체의 타입(`B`)은 고려하지 않는다.
   </details>

3. 디폴트 파라미터 값이 있으면 오버로드를 만들 필요가 없는데, Java에서 그 함수를 호출할 때는 어떤 문제가 생기고 어떻게 해결하는가?

   <details>
   <summary>답</summary>

   Java에서는 기본값 생략이 되지 않아 모든 인자를 넘겨야 한다. Kotlin 함수에 `@JvmOverloads`를 붙이면 기본값 조합별 오버로드가 생성된다.
   </details>

4. 확장 프로퍼티에서 `val String.firstChar: Char = this[0]` 처럼 초기화하면 안 되는 이유는?

   <details>
   <summary>답</summary>

   확장 프로퍼티는 클래스에 필드를 추가하는 것이 아니므로 값을 저장할 곳(backing field)이 없다. `get() = this[0]`처럼 getter를 정의해야 한다.
   </details>

5. `intArrayOf(1, 2)`를 `vararg nums: Int`를 받는 함수에 넘기는 올바른 방법은?

   <details>
   <summary>답</summary>

   spread 연산자를 써서 `sum(*arr)` 로 넘긴다.
   </details>

## 확인 필요

아래는 책 본문과 대조해 확인하지 않은 내용이다. 책의 서술 범위와 순서에 맞는지 확인이 필요하다.

- 책에서 `@JvmOverloads`, `@file:JvmName`을 이 장에서 직접 다루는지(혹은 다른 장인지) 여부
- 절의 구성과 순서(위 순서는 일반적인 흐름에 맞춘 것이며, 책의 절 번호와 제목은 확인하지 않음)
- 3중 따옴표 문자열 안의 `$` 처리 방식에 관한 책의 설명 범위
- 구조 분해 선언과 `data class`의 연결 설명이 이 장에 어느 정도 나오는지
