# 9장. 연산자 오버로딩과 다른 관례

## 한눈에 보기

이 장은 "`+`, `[]`, `in`, `..`, `for`, 구조 분해, `by` 같은 문법을 내가 만든 클래스에서도 쓰려면 어떻게 하는가?"에 답한다.

- Kotlin은 특정 이름의 함수(`plus`, `get`, `contains`, `iterator`, `componentN` 등)를 `operator`로 선언하면 그에 대응하는 문법을 쓸 수 있게 해 준다. 이 약속을 관례(convention)라고 한다.
- Java에는 연산자 오버로딩이 없다. Kotlin은 정해진 연산자만, 정해진 함수 이름으로만 오버로딩할 수 있다.
- 비교(`==`, `<`), 인덱스 접근(`[]`), 포함(`in`), 범위(`..`), 반복(`for`)도 모두 관례다.
- 구조 분해 선언은 `componentN` 함수로, 위임 프로퍼티는 `getValue`/`setValue` 함수로 구현된다.

## 핵심 개념

### 이항 산술 연산 오버로딩

`operator fun plus(...)`를 정의하면 `a + b`를 쓸 수 있다. 멤버 함수로도, 확장 함수로도 정의할 수 있다.

| 식 | 호출되는 함수 |
|---|---|
| `a + b` | `a.plus(b)` |
| `a - b` | `a.minus(b)` |
| `a * b` | `a.times(b)` |
| `a / b` | `a.div(b)` |
| `a % b` | `a.rem(b)` |

```kotlin
data class Point(val x: Int, val y: Int) {
    operator fun plus(other: Point) = Point(x + other.x, y + other.y)
}

operator fun Point.times(n: Int) = Point(x * n, y * n)

fun main() {
    val p = Point(1, 2) + Point(3, 4)
    println(p)
    println(p * 2)
    // 출력:
    // Point(x=4, y=6)
    // Point(x=8, y=12)
}
```

`operator` 키워드를 빼먹으면 `+`로 호출할 수 없다. 피연산자 타입이 달라도 된다(`Point * Int`). 단, `2 * p`처럼 순서를 바꾸려면 `Int.times(Point)` 확장을 따로 정의해야 한다.

> 💡 **눈높이 설명**
>
> Java에서 `BigDecimal`을 `a.add(b)`로 써야 하는 불편이 연산자 오버로딩이 없어서 생긴 것이다. Kotlin은 `a + b`를 그냥 `a.plus(b)` 호출로 번역하는 문법 설탕이어서, 특별한 마법 없이 함수 이름만 맞추면 된다. 실제로 Kotlin 표준 라이브러리의 `BigDecimal`에는 `plus` 확장이 있어 `a + b`로 쓸 수 있다.

### 복합 대입 연산자 오버로딩

`+=`는 `plusAssign`이 있으면 그것을, 없으면 `a = a + b`(`plus`)로 번역된다. 두 함수를 모두 정의하면 `+=`가 모호해져 오류가 난다.

```kotlin
fun main() {
    val list = mutableListOf(1, 2)
    list += 3                      // MutableList의 plusAssign → 원본에 추가
    println(list)

    var ro = listOf(1, 2)
    ro += 3                        // ro = ro + 3 → 새 리스트
    println(ro)
    // 출력:
    // [1, 2, 3]
    // [1, 2, 3]
}
```

일반 규칙은 이렇다. 객체를 **바꾸는** 클래스(변경 가능)는 `plusAssign`을, **바꾸지 않는** 클래스(불변)는 `plus`를 정의한다. `val`에 `plus`만 있는 타입으로 `+=`를 쓰면 재대입이 필요해서 컴파일 오류가 난다.

### 단항 연산자 오버로딩

| 식 | 호출되는 함수 |
|---|---|
| `+a` | `a.unaryPlus()` |
| `-a` | `a.unaryMinus()` |
| `!a` | `a.not()` |
| `++a`, `a++` | `a.inc()` |
| `--a`, `a--` | `a.dec()` |

```kotlin
data class Point(val x: Int, val y: Int) {
    operator fun unaryMinus() = Point(-x, -y)
    operator fun inc() = Point(x + 1, y + 1)
}

fun main() {
    var p = Point(1, 2)
    println(-p)
    p++
    println(p)
    // 출력:
    // Point(x=-1, y=-2)
    // Point(x=2, y=3)
}
```

`inc`/`dec`는 객체를 직접 바꾸지 않고 **새 값을 반환**하면, 컴파일러가 변수에 다시 대입해 준다.

### 비교 연산자 오버로딩: `==`와 `equals`

`a == b`는 `a?.equals(b) ?: (b == null)`로 번역된다. null 검사를 알아서 해 주므로 `a`가 null이어도 NPE가 나지 않는다. 그래서 `equals`를 `override`해서 동등성을 정의한다. `===`는 참조 동일성 비교이며 오버로딩할 수 없다.

```kotlin
class Id(val v: Int) {
    override fun equals(other: Any?): Boolean =
        other is Id && other.v == v
    override fun hashCode() = v.hashCode()
}

fun main() {
    val a: Id? = Id(1)
    println(a == Id(1))
    println(a === Id(1))
    println(null == Id(1))
    // 출력:
    // true
    // false
    // false
}
```

`equals`는 `Any`에 이미 `operator`로 선언되어 있어서 override할 때 `operator`를 다시 붙이지 않는다. `data class`는 `equals`/`hashCode`를 자동 생성한다.

### 순서 연산자: `compareTo`

`<`, `>`, `<=`, `>=`는 `compareTo` 결과를 0과 비교하는 것으로 번역된다. `Comparable`을 구현하면 된다.

```kotlin
class Version(val major: Int, val minor: Int) : Comparable<Version> {
    override fun compareTo(other: Version) =
        compareValuesBy(this, other, { it.major }, { it.minor })
}

fun main() {
    println(Version(1, 2) < Version(1, 10))
    println(Version(2, 0) >= Version(1, 9))
    // 출력:
    // true
    // true
}
```

**Java 비교:** Java는 `a.compareTo(b) < 0`이라고 써야 한다. 객체에 `<`를 쓰는 것은 Java에서는 불가능하다.

### 인덱스로 원소 접근: `get`과 `set`

`a[i]`는 `a.get(i)`, `a[i] = v`는 `a.set(i, v)`로 번역된다. 인덱스 타입은 `Int`가 아니어도 되고, 인자가 여러 개여도 된다.

```kotlin
class Grid(private val w: Int, h: Int) {
    private val cells = IntArray(w * h)
    operator fun get(x: Int, y: Int) = cells[y * w + x]
    operator fun set(x: Int, y: Int, v: Int) { cells[y * w + x] = v }
}

fun main() {
    val g = Grid(3, 3)
    g[1, 2] = 7
    println(g[1, 2])
    // 출력: 7
}
```

`Map`에서 `map["key"]`, `map["key"] = v`를 쓰는 것도 같은 관례다.

### `in` 관례: `contains`

`x in c`는 `c.contains(x)`로, `x !in c`는 그 부정으로 번역된다.

```kotlin
class Rect(val l: Int, val t: Int, val r: Int, val b: Int) {
    operator fun contains(p: Pair<Int, Int>) =
        p.first in l until r && p.second in t until b
}

fun main() {
    val rect = Rect(0, 0, 10, 10)
    println((5 to 5) in rect)
    println((10 to 5) in rect)
    // 출력:
    // true
    // false
}
```

### 범위 만들기: `rangeTo`와 `rangeUntil`

`a..b`는 `a.rangeTo(b)`, `a..<b`는 `a.rangeUntil(b)`로 번역된다. `Comparable`을 구현한 타입이라면 표준 라이브러리의 `rangeTo` 확장이 이미 있어서 바로 쓸 수 있다.

```kotlin
fun main() {
    val a = java.time.LocalDate.of(2026, 1, 1)
    val b = java.time.LocalDate.of(2026, 12, 31)
    val range = a..b                    // ClosedRange<LocalDate>
    println(java.time.LocalDate.of(2026, 6, 1) in range)
    println(5 in 1..<5)                 // 끝 값 제외
    // 출력:
    // true
    // false
}
```

### `iterator` 관례

`for (x in c)`는 `c.iterator()`를 호출해서 `hasNext()`/`next()`로 돌린다. `iterator()`가 `operator`로 정의되어 있으면(멤버든 확장이든) `Iterable`을 구현하지 않아도 `for`에 쓸 수 있다.

```kotlin
class Countdown(val from: Int) {
    operator fun iterator() = (from downTo 1).iterator()
}

fun main() {
    for (n in Countdown(3)) print("$n ")
    // 출력: 3 2 1
}
```

> 💡 **눈높이 설명**
>
> Java의 향상된 `for`는 `Iterable`을 구현한 객체에만 쓸 수 있다. Kotlin은 인터페이스를 구현하라고 요구하는 대신 "`iterator()`라는 `operator` 함수가 있으면 된다"는 이름 규칙으로 판단한다. 내가 수정할 수 없는 외부 클래스도 확장 함수로 `for`에 쓸 수 있게 만들 수 있다는 점이 다르다.

### 구조 분해 선언과 `componentN`

`val (a, b) = obj`는 `val a = obj.component1()`, `val b = obj.component2()`로 번역된다. `data class`는 주 생성자 프로퍼티 순서대로 `componentN`을 자동 생성한다. 일반 클래스는 `operator fun componentN()`을 직접 정의한다.

```kotlin
class Name(val first: String, val last: String) {
    operator fun component1() = first
    operator fun component2() = last
}

fun main() {
    val (f, l) = Name("민준", "김")
    println("$l$f")
    val map = mapOf("a" to 1, "b" to 2)
    for ((k, v) in map) print("$k=$v ")
    // 출력:
    // 김민준
    // a=1 b=2
}
```

사용하지 않는 값은 `_`로 건너뛴다(`val (_, last) = name`).

### 위임 프로퍼티의 기본 문법과 내부 동작

프로퍼티의 getter/setter 로직을 다른 객체(위임 객체)에 맡기는 기능이다. `val/var 이름: 타입 by 위임객체`로 쓴다. 위임 객체는 `getValue`(와 `var`이면 `setValue`)를 `operator`로 가져야 한다.

```kotlin
import kotlin.reflect.KProperty

class Loud {
    private var value = ""
    operator fun getValue(thisRef: Any?, p: KProperty<*>) = value
    operator fun setValue(thisRef: Any?, p: KProperty<*>, v: String) {
        value = v.uppercase()
    }
}

class Box { var text: String by Loud() }

fun main() {
    val b = Box()
    b.text = "hello"
    println(b.text)
    // 출력: HELLO
}
```

컴파일러는 `b.text` 읽기를 위임 객체의 `getValue(b, 프로퍼티정보)` 호출로, 쓰기를 `setValue(b, 프로퍼티정보, 값)` 호출로 바꿔 준다.

> 💡 **눈높이 설명**
>
> Java에서는 같은 getter/setter 로직(로깅, 검증, 캐싱)을 여러 필드에 쓰려면 매번 복붙하거나 어노테이션과 프록시를 써야 했다. 위임 프로퍼티는 그 로직을 클래스 하나로 뽑아 두고 `by`로 필드마다 붙이는 방식이다. 상속이 아니라 합성이라 부모 클래스를 정해야 한다는 제약도 없다.

### `by lazy()`를 사용한 지연 초기화

`lazy { }`는 처음 읽을 때 딱 한 번 람다를 실행해서 값을 만들고, 이후에는 그 값을 재사용하는 위임 객체를 만든다. `val`에만 쓴다. 기본적으로 스레드 안전하다.

```kotlin
class Report {
    val data: String by lazy {
        println("계산 중...")
        "결과"
    }
}

fun main() {
    val r = Report()
    println("생성됨")
    println(r.data)
    println(r.data)
    // 출력:
    // 생성됨
    // 계산 중...
    // 결과
    // 결과
}
```

**Java 비교:** Java에서는 `null`로 두었다가 getter에서 검사하고 초기화하는 코드(더블 체크 락킹 등)를 직접 써야 했다.

## Java와 비교

| 항목 | Java | Kotlin |
|---|---|---|
| 연산자 오버로딩 | 불가 (`String`의 `+`만 언어가 지원) | `operator fun`으로 정해진 연산자만 가능 |
| 객체 덧셈 | `a.add(b)` | `a + b` (`plus`) |
| 동등 비교 | `a.equals(b)` (`==`는 참조 비교) | `a == b` (`equals`), 참조 비교는 `===` |
| 크기 비교 | `a.compareTo(b) < 0` | `a < b` (`compareTo`) |
| 컬렉션 접근 | `list.get(i)`, `map.put(k, v)` | `list[i]`, `map[k] = v` |
| 포함 검사 | `c.contains(x)` | `x in c` |
| 향상된 `for` | `Iterable` 구현 필요 | `operator fun iterator()`만 있으면 됨 |
| 여러 값 풀기 | 없음 | `val (a, b) = obj` (`componentN`) |
| getter/setter 재사용 | 복붙, 프록시, 어노테이션 | `by` 위임 프로퍼티 |
| 지연 초기화 | null 검사 + 수동 동기화 | `by lazy { }` |

## 헷갈리기 쉬운 점

- `operator`를 빼먹으면 이름이 맞아도 연산자 문법을 쓸 수 없다. 반대로 이름이 다르면 `operator`를 붙여도 대응되지 않는다.
- 연산자 우선순위는 바꿀 수 없다. `a + b * c`의 우선순위는 함수 이름이 아니라 연산자가 결정한다.
- `+=`는 `plus`와 `plusAssign` 둘 중 하나로 풀린다. 둘 다 있으면 모호하다는 컴파일 오류가 난다.
- `val list = listOf(1)`에 `list += 2`는 `val`을 재대입해야 해서 오류다. `var`로 바꾸거나 `mutableListOf`를 쓴다.
- `==`는 값 비교(`equals`), `===`는 참조 비교다. Java의 `==`와 의미가 반대에 가깝다.
- `equals`를 override하면 `hashCode`도 함께 맞춰야 한다. 해시 기반 컬렉션에서 오동작한다.
- 구조 분해는 이름이 아니라 **순서**로 대응된다. `data class` 프로퍼티 순서를 바꾸면 분해 결과가 달라진다.
- `by lazy`는 `val` 전용이다. `var`처럼 값을 다시 바꾸고 싶으면 다른 위임을 써야 한다.

## 스스로 점검

1. `a + b`가 컴파일되려면 어떤 함수가 있어야 하고, 멤버가 아니라 확장으로 정의해도 되는가?

<details>
<summary>답 보기</summary>

`operator fun plus(...)`가 있어야 한다. 멤버 함수든 확장 함수든 상관없다. 수정할 수 없는 외부 클래스에도 확장으로 연산자를 추가할 수 있다.

</details>

2. `val list = mutableListOf(1)`에서 `list += 2`가 되는 이유와, `val list = listOf(1)`에서 안 되는 이유는?

<details>
<summary>답 보기</summary>

`MutableList`에는 `plusAssign`이 있어 원본에 추가하므로 `val`이어도 된다. `listOf`의 `List`는 `plus`만 있어서 `list = list + 2`로 재대입해야 하는데 `val`이라 불가능하다. `var`로 바꾸면 된다.

</details>

3. `a == b`와 `a === b`는 각각 무엇을 비교하고, 어느 쪽을 오버로딩할 수 있는가?

<details>
<summary>답 보기</summary>

`==`는 `equals`로 값(동등성)을 비교하며 `equals`를 override해서 바꿀 수 있다. `===`는 참조 동일성 비교이며 오버로딩할 수 없다.

</details>

4. 내가 만든 클래스를 `for (x in obj)`와 `val (a, b) = obj`에 쓰려면 각각 무엇을 정의해야 하는가?

<details>
<summary>답 보기</summary>

`for`에는 `operator fun iterator()`가, 구조 분해에는 `operator fun component1()`, `component2()`가 필요하다. `data class`로 만들면 `componentN`은 자동으로 생긴다.

</details>

5. `by lazy`는 언제 람다를 실행하고, 몇 번 실행하는가?

<details>
<summary>답 보기</summary>

프로퍼티를 처음 읽을 때 한 번만 실행한다. 이후에는 저장된 값을 반환한다.

</details>
